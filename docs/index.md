# Pidgin Host Provider

The Pidgin Host provider manages resources in the [Pidgin Host](https://www.pidginhost.com) cloud: servers, private networks, public and floating IPs, firewalls, volumes, object storage buckets and SSH keys.

This is an independent, community-maintained provider. It is not the official
`pidginhost/pidginhost` provider.

It works with Terraform 1.6 and later and with OpenTofu 1.8 and later.

## Example Usage

```terraform
terraform {
  required_providers {
    pidginhost = {
      source = "mihai-amihailesei/pidginhost"
    }
  }
}

# The token is read from the PIDGINHOST_TOKEN environment variable when it is
# not set here. Never commit a token to version control.
provider "pidginhost" {}
```

## Authentication

The provider authenticates with an API token, sent as
`Authorization: Token <token>`. Create a token in the Pidgin Host control
panel and provide it in one of two ways:

- the `PIDGINHOST_TOKEN` environment variable (recommended), or
- the `token` argument, ideally from a variable or secret store rather than a
  literal in the configuration.

```shell
export PIDGINHOST_TOKEN="..."
terraform plan
```

## Behavior common to all resources

- **Import.** Every resource can be imported. The import ID format is given on
  each resource's page.
- **Timeouts.** Every resource accepts a `timeouts` block. Asynchronous
  operations (server and bucket creation, package changes, deletions) are
  polled until they finish or the timeout expires.
- **Drift.** Every refresh reads the resource from the API. A resource deleted
  outside Terraform is removed from the state and planned for creation.
- **Sensitive values in state.** Server passwords and bucket credentials are
  marked sensitive, which hides them in plan output, but they are stored in
  the state in plain text. Use an encrypted, access-controlled state backend
  (or OpenTofu state encryption).
